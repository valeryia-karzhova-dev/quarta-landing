# Кварта: лендинг обжарки (Next.js)

Next.js (App Router) + TypeScript. Одностраничник с формой заявки и эндпоинтом `POST /api/lead`.

## Запуск
```
npm install
cp .env.example .env.local   # без Turso заявки пишутся в локальный файл local.db
npm run dev
```
Деплой: репозиторий на GitHub, импорт в Vercel, переменные из `.env.example` задать в настройках проекта.

## Хранилище заявок: Turso (SQLite в облаке)
Файл и локальный SQLite на Vercel не подходят: файловая система функций временная, записи пропадут. Turso даёт обычный SQL, бесплатный тариф и выгрузку данных. Таблица создаётся автоматически при первой заявке (`lib/db.ts`).

## Как работает форма
- Телефон: белорусские мобильные (коды 25, 29, 33, 44), форматы `+375…`, `80…`, `375…`, без кода страны. Проверка на клиенте и на сервере (`lib/phone.ts`).
- Дубли: один атомарный `INSERT … WHERE NOT EXISTS` по номеру за 10 минут, поэтому двойной клик и параллельные запросы дают одну запись. Повтор возвращает `200 duplicate`, пользователь видит успех.
- Сбой: при ошибке сети или `5xx` форма показывает сообщение, данные остаются, есть телефон и Telegram. Если БД не записала, но Telegram получил заявку, она считается принятой.
- Источник: UTM, `yclid`, `fbclid`, `gclid`, страница входа и реферер сохраняются на клиенте (first touch) и уходят вместе с заявкой в БД и в Telegram.
  Пример ссылки для рекламы: `https://site/?utm_source=instagram&utm_medium=cpc&utm_campaign=autumn&utm_content=ad3`

## Допущения
- Контакты (телефон, Telegram, Instagram) вымышленные, замените в `app/page.tsx` и `components/LeadForm.tsx`.
- Городские номера не принимаются.
- Для превью ссылок временно используется `public/hero.jpg`; лучше сделать отдельную картинку 1200×630.
- Фото в `public/` (hero, footer, fresh-coffee, barista) предоставлены заказчиком. Иконка сайта: `app/icon.svg`.
